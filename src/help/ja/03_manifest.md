# マニフェスト

1 行が 1 スキーマです。行を開くと、そのスキーマの診断とスキーマ単位の設定を扱えます。

## 手順

1. manifest が無いスキーマを選び、「カタログから起こす」を押す。
   `draft_manifest()` が `pg_proc` を読んで骨子を作り、保存済みの宣言へマージします。
   既存の宣言は書き換わりません（足すだけです）。
2. 行を開いて診断を確認する。error が 1 件でもあると生成は止まります。
3. 「この箇所を開く」で、原因の関数のオペレーション編集へ飛びます。
4. profiles と defaults を確認する。

## 診断

- **error** — compile を止めます。宣言と `pg_proc` の食い違い、bind 漏れなど
- **warning** — 生成はできますが確認したい事柄
- **info** — 公開関数だが宣言が無い、など。既定拒否で非公開になっているだけで異常ではありません

診断は最初の 1 件で止まらず全件出ます。1 回の確認で直す箇所を全部把握できます。

## defaults

全 operation へ浅くマージされます。同じキーは operation 側が勝ちます。
`operationGroup` / `tags` / `security` を関数の数だけ書かずに済ませるための圧縮です。
